Lovable to Shopify: move one section, not a whole app

A practical Lovable-to-Shopify section workflow: native Liquid versus headless, supported markup, editable settings and safe installation.

Updated November 6, 2026 · Static conversion, not whole-store migration

Choose native theme or headless first

Lovable output is usually React. Connecting that React site to Shopify through a commerce API keeps a separate front end; it does not automatically create a Liquid file inside your theme. A native Online Store 2.0 section is different: Shopify renders the file and the theme editor exposes its schema settings. SectionStitch only targets that second, narrower result. It does not turn authentication, orders, products or a database into Shopify features.

Start with the smallest visual component

Find one hero, FAQ or feature grid in source code you own. Include local helper components if they contain the actual markup. Remove imports that only provide a button or icon, replacing those with ordinary HTML when possible. Keep literal text, image descriptions, static Tailwind classes and direct links. The bundled hero sample is derived from the MIT TailGrids hero: navigation and client logos were explicitly removed from the single-section scope, and the external illustration was replaced. Those omissions are not successful conversions of a navbar.

Turn a feature card into merchant controls

The feature demo shows the essential change: repeated card text becomes block.settings values while the heading remains a section setting. The rendered visual layout is not the entire acceptance test. A merchant must be able to change copy and reorder cards without editing code.

<h2>{{ section.settings.heading | escape }}</h2>
<div class="features">
  {% for block in section.blocks %}
    <article {{ block.shopify_attributes }}>
      <h3>{{ block.settings.title | escape }}</h3>
      <p>{{ block.settings.body | escape }}</p>
    </article>
  {% endfor %}
</div>

Validate before migration

Paste the component into the free tool, read every unsupported-expression and missing-CSS warning, then download a new section file. Use a duplicate theme and select images again. Test changed copy, mobile layout, links, image alt text and block ordering. Reliquify and LovableConverter target related migration work; this free local static converter does not claim their full-store capabilities. A lint pass cannot prove a finished migration.

References and next steps
