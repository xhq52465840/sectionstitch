An accessible Shopify FAQ section with native details and blocks

Build a Shopify FAQ accordion without a JavaScript framework: native disclosure controls, editable question blocks, keyboard checks and scoped styles.

Updated November 6, 2026 · Static conversion, not whole-store migration

Use native disclosure for a simple FAQ

A marketing FAQ usually does not need React state or an accordion framework. A details element with summary already provides open/closed behavior and keyboard operation. Its expanded state belongs to the browser, so avoid hard-coding aria-expanded on summary without code to keep it synchronized. Use meaningful question text, visible focus and ordinary paragraph answers. This remains a simple disclosure pattern, not a promise that every custom multi-panel interaction is accessible.

Render each question as an editor block

The MIT FAQ demo is based on a React helper with state. The browser converter recognizes a limited question/answer helper pattern and replaces it with native disclosure, with a warning that the layout has changed. General event-driven components are not migrated. A hand-reviewed block loop gives the merchant add, edit and reorder controls.

{% for block in section.blocks %}
  <details {{ block.shopify_attributes }}>
    <summary>{{ block.settings.question | escape }}</summary>
    <p>{{ block.settings.answer | escape }}</p>
  </details>
{% endfor %}
<style>
#shopify-section-{{ section.id }} summary { cursor: pointer; }
#shopify-section-{{ section.id }} summary:focus-visible {
  outline: 3px solid #3758f9; outline-offset: 4px;
}
</style>

Give the loop a matching schema

Define a question block with a text question and textarea answer, then include at least one question in the preset. The setting IDs in the schema and markup must agree. Keep longer answers readable on narrow phones. If you want rich answers with links, use an intentional richtext setting and review its rendering rather than putting HTML in an escaped textarea.

{"type":"question","name":"Question","settings":[
  {"type":"text","id":"question","label":"Question","default":"How does it work?"},
  {"type":"textarea","id":"answer","label":"Answer","default":"Add your own explanation."}
]}

Test behavior and repeated instances

Tab to every summary and toggle it with Enter or Space. Confirm that focus remains visible and that opened answers do not create horizontal overflow. Add two copies of the FAQ to one page; decorative SVG gradient IDs must be unique across instances. Avoid forcing exclusive-open behavior unless it is needed and tested. Local screenshots and a lint pass are useful checks, but the actual theme editor and storefront still need validation after installation.
