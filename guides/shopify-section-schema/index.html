Shopify section schema: settings, blocks and presets explained

A compact Shopify schema reference with a real feature-grid example, common validation errors, image picker defaults and block rendering.

Updated November 6, 2026 · Static conversion, not whole-store migration

Schema is configuration JSON, not a second template

A section may contain one schema tag with valid JSON. The schema name appears in the theme editor. Settings define merchant controls; they do not render themselves. Output the corresponding section.settings values in Liquid. IDs must be unique within each settings scope, and JSON comments or trailing commas can prevent saving. The generated feature grid follows the same structure as the compact reference below.

{% schema %}
{
  "name": "Feature grid",
  "settings": [{"type":"text","id":"heading","label":"Heading","default":"What we offer"}],
  "blocks": [{"type":"feature","name":"Feature","settings":[
    {"type":"text","id":"title","label":"Title","default":"Refreshing design"},
    {"type":"textarea","id":"body","label":"Description","default":"Describe the benefit."}
  ]}],
  "presets": [{"name":"Feature grid","blocks":[{"type":"feature"},{"type":"feature"}]}]
}
{% endschema %}

Blocks separate editable items from the overall heading

The overall heading belongs to section.settings. Each feature’s title and description belong to block.settings. A block definition describes the type of item; presets populate initial items. Without a loop the controls can exist but have no effect. Use block.shopify_attributes on the item’s wrapper so the editor can associate its selection with the visible card.

<h2>{{ section.settings.heading | escape }}</h2>
<div class="features">
  {% for block in section.blocks %}
    <article {{ block.shopify_attributes }}>
      <h3>{{ block.settings.title | escape }}</h3>
      <p>{{ block.settings.body | escape }}</p>
    </article>
  {% endfor %}
</div>

Pick the setting type for the actual content

Use text for a short heading, textarea for longer plain copy, url for destinations, image_picker for images and color for an editable color. Plain text should be escaped; richtext settings contain markup and need a separate deliberate rendering strategy. An image_picker has no external-URL default. Blank input values and translated text can change layout, so test them, not just the initial preset. This converter exposes supported static colors but does not infer a complete design system.

Check references and limits before debugging CSS

A preset block’s type must match a block definition, and the Liquid lookup must use the same setting ID. Shopify currently allows up to 50 blocks in a section; use a smaller sensible max_blocks when appropriate. This tool limits its own inference and input size to keep output reviewable. Schema correctness is necessary but does not prove the card order, mobile layout or editor behavior. The authoritative reference is linked below; use it when changing supported attributes.
